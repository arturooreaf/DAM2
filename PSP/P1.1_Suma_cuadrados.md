## 2. Código

```python
import multiprocessing as mp
import os
import platform
from concurrent.futures import ProcessPoolExecutor
from time import perf_counter


def crear_lotes(datos, tamano):
    # Devuelve una lista de tuplas (numero_de_lote, lista_de_valores).
    lotes = []
    numero = 1
    for inicio in range(0, len(datos), tamano):
        lotes.append((numero, datos[inicio:inicio + tamano]))
        numero += 1
    return lotes


def procesar_lote(lote):
    # Funcion trabajadora: definida a nivel de modulo para que spawn la encuentre.
    numero, valores = lote
    suma = 0
    for n in valores:
        suma += n * n
    return {
        "lote": numero,
        "pid": os.getpid(),
        "cantidad": len(valores),
        "suma": suma,
    }


def version_secuencial(lotes):
    # Todo lo hace el proceso principal, lote a lote.
    resultados = []
    for lote in lotes:
        resultados.append(procesar_lote(lote))
    return resultados


def version_procesos(lotes):
    # Un unico pool para todos los lotes. El with cierra el pool al salir.
    ctx = mp.get_context("spawn")
    with ProcessPoolExecutor(max_workers=2, mp_context=ctx) as pool:
        resultados = list(pool.map(procesar_lote, lotes))
    return resultados


def comprobar(resultados, lotes, datos):
    # Cada lote aparece una sola vez y se han procesado todos los numeros.
    esperados = sorted(numero for numero, _ in lotes)
    recibidos = sorted(r["lote"] for r in resultados)
    lotes_ok = esperados == recibidos
    cantidad = sum(r["cantidad"] for r in resultados)
    cantidad_ok = cantidad == len(datos)
    print(f"  Lotes sin repetir ni faltar: {'OK' if lotes_ok else 'FALLO'}")
    print(f"  Numeros procesados: {cantidad} de {len(datos)} -> {'OK' if cantidad_ok else 'FALLO'}")
    return lotes_ok and cantidad_ok


def mostrar(resultados):
    for r in resultados:
        print(f"  Lote {r['lote']}: PID {r['pid']}, {r['cantidad']} numeros, suma parcial {r['suma']}")


def ejecutar_caso(nombre, datos, tamano, solo_procesos=False):
    print(f"\n=== {nombre} (datos={len(datos)}, tamano de lote={tamano}) ===")
    lotes = crear_lotes(datos, tamano)

    total_sec = None
    if not solo_procesos:
        res_sec = version_secuencial(lotes)
        total_sec = sum(r["suma"] for r in res_sec)
        print(f"Secuencial: total = {total_sec}")

    try:
        res_proc = version_procesos(lotes)
    except TypeError as e:
        # El error ocurrio en un trabajador; pool.map lo relanza en el principal.
        print(f"ERROR en un trabajador: {e}")
        print("No se muestra total: el resultado estaria incompleto.")
        return

    print("Procesos:")
    mostrar(res_proc)
    pids = sorted({r["pid"] for r in res_proc})
    print(f"  PIDs de trabajadores distintos: {pids}")
    comprobar(res_proc, lotes, datos)
    total_proc = sum(r["suma"] for r in res_proc)
    print(f"Procesos: total = {total_proc}")
    if total_sec is not None:
        iguales = total_sec == total_proc
        print(f"Totales iguales: {'SI' if iguales else 'NO'}")


def medir_tiempos(datos, tamano, repeticiones=3):
    lotes = crear_lotes(datos, tamano)
    filas = []
    for i in range(1, repeticiones + 1):
        inicio = perf_counter()
        version_secuencial(lotes)
        t_sec = perf_counter() - inicio

        inicio = perf_counter()
        version_procesos(lotes)  # incluye crear y cerrar el pool
        t_proc = perf_counter() - inicio
        filas.append((i, t_sec, t_proc))

    print("\n=== Tiempos (segundos) ===")
    print("Ejecucion | Secuencial | Procesos")
    for i, t_sec, t_proc in filas:
        print(f"{i:9} | {t_sec:10.6f} | {t_proc:8.4f}")


def main():
    print(f"PID del proceso principal: {os.getpid()}")
    print(f"Python {platform.python_version()} en {platform.system()} {platform.release()}")

    ejecutar_caso("Caso principal 1..50", list(range(1, 51)), 7)
    ejecutar_caso("Prueba 1: lote incompleto", [1, 2, 3], 2)
    ejecutar_caso("Prueba 2: lista vacia", [], 7)
    ejecutar_caso("Prueba 3: error en una tarea", [1, "error", 3], 2, solo_procesos=True)

    medir_tiempos(list(range(1, 51)), 7)


if __name__ == "__main__":
    main()
```

## 3. Qué hace cada parte

| Función | Quién la ejecuta | Qué hace |
|---|---|---|
| `crear_lotes` | Principal | Parte los datos en lotes de 7 y los numera (1..8) |
| `procesar_lote` | **Trabajador** (o el principal en la versión secuencial) | Suma los cuadrados de un lote y devuelve lote, PID, cantidad y suma |
| `version_secuencial` | Principal | Llama a `procesar_lote` para cada lote, uno detrás de otro |
| `version_procesos` | Principal | Crea **un pool** de 2 trabajadores con `spawn` y reparte los lotes con `map` |
| `comprobar` | Principal | Mira que ningún lote falta ni se repite y que hay 50 números |
| `medir_tiempos` | Principal | Mide 3 veces cada versión con `perf_counter` |

**Cómo leerla:**

1. **PID 5704** es el principal (coordinador). No aparece en ningún lote: él no calcula, reparte.
2. Solo hay **2 PIDs** de trabajadores (17712 y 21396) para **8 lotes**: cada trabajador hace varios lotes.
3. Los PIDs cambian en cada ejecución. No hay que memorizarlos.

## 6. Tiempos (1..50, lotes de 7)

| Ejecución | Secuencial (s) | Procesos (s) |
|---|---|---|
| 1 | 0.000025 | 0.3127 |
| 2 | 0.000022 | 0.3389 |
| 3 | 0.000024 | 0.3049 |

**Comentario:** la versión con procesos es **miles de veces más lenta**. No es un fallo del código: sumar 50 cuadrados es casi nada, y crear el pool (arrancar 2 intérpretes nuevos con `spawn`), enviar los lotes y devolver los resultados cuesta mucho más que el cálculo. Repartir solo compensa con trabajos **CPU-bound grandes**.

## 7. Preguntas de la memoria

**a) ¿Cuántos datos, lotes y trabajadores? ¿Qué has observado en los PIDs?**
50 datos, 8 lotes (7 de 7 números y 1 con el 50) y 2 trabajadores. Solo aparecen 2 PIDs distintos y se repiten en varios lotes: el pool **reutiliza** sus trabajadores. Ocho lotes no son ocho procesos. El PID del principal no aparece en los lotes.

**b) ¿Por qué devuelve cada trabajador su resultado en vez de acumularlo en una variable global del principal?**
Porque cada proceso tiene su **memoria aislada**. Si el trabajador modificara una variable global, modificaría su propia copia y el principal nunca vería el cambio. Por eso el resultado vuelve de forma explícita (con `return`, que el pool envía al principal serializado con pickle).

**c) ¿Para qué sirven `spawn`, la protección `__main__` y el bloque `with`?**
- **`spawn`**: arranca cada trabajador como un intérprete de Python nuevo. Es el método de Windows y hace que el comportamiento sea igual en todos los sistemas.
- **`if __name__ == "__main__"`**: con `spawn`, el hijo importa el archivo. La protección evita que, al importarlo, vuelva a ejecutar `main()` y cree más procesos sin fin.
- **`with`**: cierra el pool al salir del bloque, espera a que terminen los trabajadores y libera los recursos, aunque haya un error.

**d) ¿Cómo recoges los resultados? Si usas `map`, ¿su orden demuestra el orden en que terminaron?**
Con `pool.map(procesar_lote, lotes)`, convertido en lista. **No**: `map` entrega los resultados **en el orden de entrada** (lote 1, 2, 3...), aunque los trabajadores los hayan terminado en otro orden. Por eso cada resultado lleva su número de lote.
